# Immich Duplicate Detection Finding Nothing? What It Does and Doesn't Compare

People expect duplicate detection to behave like a file deduplicator. It doesn't, and that explains most "it's broken" reports.

## 1. What it actually does

Immich's duplicate detection uses **machine-learning embeddings** — it compares what images *look like*, not their filenames or checksums. Consequences:

- Two files with the **same name and slightly different size** may not be flagged (documented)
- **Videos** are detected far less reliably than photos
- Visually near-identical shots (burst frames) *are* flagged, which some people consider false positives
- There's a **similarity threshold**; below it, nothing is reported

So "it didn't find my obvious duplicate" is often correct behaviour for the algorithm, not a bug.

Exact-duplicate uploads are handled separately: Immich rejects a re-upload of a file whose checksum it already has. That's why re-uploading the same photo doesn't create a second asset — and why it never appears in the duplicates list.

## 2. The ML job has to have run

Duplicate detection depends on embeddings, which come from the **machine learning** container:

- **Administration → Jobs → Duplicate Detection** must have run (and **Smart Search** before it, since both use embeddings)
- If `immich-machine-learning` is crash-looping, nothing is generated — and the duplicates page is simply empty
- After importing a large library, run the jobs for **all assets**, not just missing ones

Check the job queue counts. Zero processed assets means the pipeline, not the algorithm.

## 3. Stacked assets are excluded

Documented: duplicate detection **does not show assets that are already stacked**. If you (or an import tool) stacked photos, they're out of scope.

So the workflow "stack everything, then look for duplicates" produces an empty list by design. Unstack first if you want them compared.

## 4. External libraries and read-only paths

- Reported: duplicates **inside a shared album** added by a second user aren't checked at upload
- **Read-only external libraries** limit what Immich can do with what it finds — detection may run, but you can't delete the file from Immich
- Assets from different libraries can be flagged against each other, which is useful but surprising

If your library is external and read-only, treat the duplicates page as a **report** and act on the filesystem instead.

## 5. Detection is not resolution

The job **finds** candidates; you still have to resolve them in the **Utilities → Duplicates** view. A reported complaint is "duplicates are never resolved" — because nothing resolves them automatically. There's no safe auto-delete, and you wouldn't want one.

For bulk work, people use **immich-go** or the API rather than clicking through thousands of pairs. Do a dry run first, always.

## 6. When it really is broken

- `immich-machine-learning` restarting (memory, model cache, mixed image versions)
- The **model** changed between versions — embeddings generated by an older model aren't comparable; a major version may require re-running Smart Search and Duplicate Detection for everything
- Database under pressure: the similarity query is expensive, and on a small box it can time out

```bash
docker compose logs --tail=100 immich_machine_learning
docker compose logs --tail=100 immich_server | grep -i -e duplicate -e embedding
```

## Prevention / expectations

1. Run **Smart Search** then **Duplicate Detection** for all assets after a bulk import
2. Don't stack what you want deduplicated
3. Treat it as **assistive**, not authoritative — check pairs before deleting
4. **Pin the server version**; model changes mean re-running jobs
5. Keep a real backup: deleting duplicates is deleting photos

## FAQ

**Does it compare file hashes?**
Exact-duplicate uploads are blocked by checksum, but the duplicates feature compares visual embeddings.

**Why aren't videos detected?**
Detection is far weaker for video; that's a known limitation.

**Why is my duplicates list empty?**
Either the ML job hasn't run (or is crashing), or your candidates are stacked and therefore excluded.

**Can it delete duplicates automatically?**
No, and that's deliberate. Resolution is manual, or scripted via the API at your own risk.
